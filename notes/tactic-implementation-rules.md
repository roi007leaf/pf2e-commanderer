## Native API / Rule Element evidence

- Installed `systems/pf2e/pf2e.mjs:41388`, `StrikeRuleElement.defineSchema`: `category:"martial"`, `range:{max:200}`, `damage:{base:{dice:10,die:"d12",damageType:"piercing"}}` are supported for temporary Insta-Ballista Strike. Use native Strike preparation/roll so proficiency/DEX/MAP follow core semantics; scope item FlatModifier to generated Strike. No persistent inventory ballista required.
- `systems/pf2e/pf2e.mjs:39362`, `AdjustStrikeRuleElement.VALID_PROPERTIES`: materials, property-runes, range-increment, traits, weapon-traits. No partial-ignore-resistance property or standalone IgnoreResistance RE exists in registry at line44849.
- `systems/pf2e/pf2e.mjs:30799` damage IWR processor: `DamageRoll.options.bypass.resistance.ignore` creates Resistance entries, then marks a matching resistance ignored outright with `l.some(e=>e.test(p))`. Its `max` does not implement subtracting level from a resistance. Piranha must not simply inject `{type,max:level}` claiming partial reduction. An integration must reduce eligible resistances temporarily only in the designated source/target damage-application context, restore afterward, and avoid race/repeated-application errors; otherwise guide user through correction.
- `scripts/foundry/effects.js:grantPiranhaAssault` currently only adds RollOption + RollNote, so current description is reminder-only. `grantShadowsInMoonlight` is also only RollNote; `grantWaitForIt` currently always grants AC/save modifier with no posture gate.
- Source text durations frequently say END commander next turn. Generic effect helper defaults START; every new grant must choose proper expiry and origin initiative explicitly. Receiver-based effects (Slip and Sizzle, Protective Screen, activated Alley-Oop ammunition) must use RECEIVER turn anchor instead.
- `scripts/domain/tactics.js` selection/response declarations cover 37, but workflows omit several aftermaths. Do not equate registration with complete mechanics.

No production files changed by this audit. Final implementation must independently validate permissions, cancellation, duplicate clicks, resource expenditure, ownership/GM authority, and combat expiry.
